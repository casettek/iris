# Fixed two-page inference tiles

The inference stages use one fixed variant: two existing weight pages per
matrix or output-head tile. This applies to auxiliary projections, all nine
transformer projection sites, and logits, in both prefill and decode. It
introduces no runtime parameter, program variant selection, storage change,
or change to stage boundaries. Raster library sources are unchanged.

## Authoring review

The repository's Raster authoring skill was followed. Each targeted recur
still iterates the real `.pages` list. `chunk = 2` is a literal pinned in the
CFS, and the tile receives `RecurInput<Block<BytesPage>>`. Page processing
stays inside no-std tiles, in the original order, using each page's original
offset. Logits append to the existing output draft; projection accumulators
keep their existing fixed shape. No host loop, synthetic counter list, or
runtime storage handle was added to the authored stages.

The generated CFS contains all 11 targeted sites with chunk size 2 and their
original entry, sequence-scope, and prior-output bindings. Attention and
cache-copy sites retain chunk size 64. Native matrix kernels are unchanged.

## Validation

- The three tile libraries passed `cargo check --locked --lib
  --no-default-features`.
- The three `tile_chunking` integration tests passed. Each covers empty
  input, one short page, two full pages, and three pages with a short final
  page. They check independently calculated signed fixed-point outputs and
  actual traced iteration counts, including three pages executing in two
  tile invocations. Logit tests also check every token ID and append order.
- The existing independent arithmetic golden-vector tests passed.
- All three programs rebuilt with `cargo raster build --backend risc0` and
  passed `cargo raster program --verify`. Their `Raster.lock` files were
  regenerated by Raster, not edited manually.
- Plain execution of the three changed stages in both prefill and decode
  matched previously recorded native outputs byte for byte.
- All six standalone stage executions passed authenticated commit/audit
  round-trips and matched the saved native outputs. Prefill checks used
  32-step proof windows (the output head used the 33-token corpus case).
  The one-token decode auxiliary and output-head traces required a two-step
  window because they contain fewer than 33 steps; decode range used 32.
- Two authenticated three-stage chains linked auxiliary projection, layer 3,
  and output-head projection for prefill and decode. Both passed
  `chain audit --execution`, and all six outputs matched the saved native
  reference. These are focused chain slices, not a complete authenticated
  inference run.
- A complete 25-stage short-case Raster run (`--no-auth`) matched the saved
  native output bytes at every stage, with the same stage inventory. This
  comparison uses the existing successful parity run
  `target/parity/1789065679358018000-22423`, not a newly executed native run.

Detailed logs and comparison reports are under `target/tile-chunk-validation`.
The fixed size is an initial choice, not a measured optimum for zkVM cost.

## Direct zkVM replay

Captured authenticated two-page inputs from the short corpus case were
executed with the rebuilt RISC Zero guests and Raster's version-matched
in-process executor. Guest journal output bytes matched the native trace
exactly, and the guest journal reported two consumed pages:

- Transformer MAC: 264,740 serialized input bytes; 30,753,175 user cycles.
- Auxiliary MAC: the same two-page matrix fixture and compatible input
  layout also matched the native result in 30,753,175 user cycles.
- Logit projection: 263,304 serialized input bytes; 33,417,041 user cycles.

These fixtures have a short second page. They are replay measurements for
these inputs, not worst-case bounds for two full pages, proof-generation
benchmarks, or production-model tuning. The tile annotations' cycle estimates
are rough scheduling hints inherited from the previous one-page estimate
and scaled by two; they must not be used as zkVM replay budgets.

## Full parity gate blocked

`just test-parity` was attempted with the existing host-build settings. It
fails at compilation because the unchanged native-staged loader at
`crates/inference/staged/src/artifact_io.rs:26` calls
`raster_runtime::install_file_source_resolver`, which is absent from the
current Raster checkout. The failure is recorded in
`target/tile-chunk-parity.log`. The full three-path gate has **not passed**
for this change; the focused tests and saved-reference comparisons above
do not replace it. Resolving the native-loader compatibility issue remains
separate from this tile-sizing patch.
